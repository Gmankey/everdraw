# M0 Pass 2 — V5.1 Seam Test

**Task:** Design V5.1 CampaignManager on paper against frozen V5.0 interfaces. If it cannot be done without changing core, V5.0 fails.

## One-Page CampaignManager Sketch

`CampaignManager` is an external authorized ClaimManager distribution source and prize funder.

- `createCampaign(prizeToken, budget, drawFrequency, eligibilityRoot, winnerConfig, metadata)` stores campaign config, validates `prizeToken` against the V5.0 allowlist path, and takes custody of campaign budget.
- For each campaign draw, CampaignManager derives `sourceKey = keccak256(campaignId, campaignDrawId)` and registers a distribution through ClaimManager. ClaimManager derives `distributionId = keccak256(CampaignManager, sourceKey)`, so campaign distributions cannot collide with DrawManager or other future sources.
- Campaign eligibility is bound through ClaimManager's opaque metadata slot. The off-chain algorithm version filters the account set by the campaign's eligibility root before TWAB-weighted sampling.
- Campaign prize legs use the same `(token, amount)` leg model as V5.0 reward funding. CampaignManager can schedule legs across draws by calling the same funding/escrow path.
- Leaves remain `(LEAF_DOMAIN, distributionId, leafIndex, account, token, amount)`. No campaign-specific field is added to the leaf encoding.
- Claiming, per-leaf deferral, non-pausability, keeper batch execution, and self-claim all remain ClaimManager behavior.

# Builder ticket — V4.1: native shMON direct deposit

**Implements:** ADR-0035. **Do not deviate from the ADR without updating it in the same change.**
**Branch:** `feat/v4.1-shmon-deposit` off `staging`. PR must pass the `contracts` CI check.

## Scope (additive only — native MON path stays unchanged)

### 1. `src/interfaces/IYieldVault.sol`
Add the one missing method:
```solidity
function transferFrom(address from, address to, uint256 amount) external returns (bool);
```
(`previewDeposit`, `transfer`, `balanceOf` already present.)

### 2. `src/TicketPrizePoolV4.sol`

**Bump** `VERSION` constant `4.0.0` → `4.1.0`.

**Add `buyTicketsShmon(uint32 ticketCount)`** — external, `whenNotPaused`, `nonReentrant`:
- Revert unless `depositMode == DepositMode.Native` (this path supplies the yield-vault's own shares directly; only meaningful for the native/shMON vault). Use a clear custom error, e.g. `ShmonPathNativeOnly`.
- Guards mirror `_buyTickets`: `stoppedAt != 0 → VaultIsStopped`; `currentRoundId` round must be `Open`; `block.timestamp < r.salesEndTime`; `ticketCount != 0`.
- `monCost = uint256(ticketCount) * r.ticketPriceAtRoundOpen` (same per-round price snapshot MON buys use).
- `uint256 requiredShares = yieldVault.previewDeposit(monCost);` — this mirrors exactly what the native path's `yieldVault.deposit(monCost)` mints, so a MON depositor and an shMON depositor paying the same `monCost` end up holding the **same** shares. (Rounding direction: `previewDeposit` rounds down, identical to the native deposit — confirm with the auditor that this does not let the shMON path under-collect relative to MON; if it does, round up and document. Do **not** silently change the equivalence basis.)
- Pull shMON transfer-safely: snapshot `yieldVault.balanceOf(address(this))` before, `yieldVault.transferFrom(msg.sender, address(this), requiredShares)`, require `after - before == requiredShares` (revert `BadAssetTransfer` otherwise). **No `yieldVault.deposit` call** — shares arrive directly.
- Credit **identically to `_buyTickets`**, using `monCost` for asset accounting and the received shares for share accounting:
  `principalAsset[rid][msg.sender] += monCost; principalShares[rid][msg.sender] += requiredShares; r.totalPrincipalAsset += monCost; r.totalPrincipalShares += requiredShares; totalUnclaimedShares += requiredShares; _activePrincipal[msg.sender] += monCost; _totalSupply += monCost;` then the **same** ticket-range append/extend logic and `type(uint32).max` overflow guard as `_buyTickets`.
- Emit `Deposit(msg.sender, monCost)` and `TicketsBought(rid, msg.sender, ticketCount, monCost)` — same events as MON buys, so indexer/Merkl need no special-casing.
- Factor the shared range/accounting tail of `_buyTickets` into an internal helper if cleaner, but **must not change** the native path's behaviour or gas-relevant storage layout in a way that breaks existing tests.

**Add `getWithdrawableShares(uint256 rid, address user) external view returns (uint256)`** — pure read of the exact amount `withdrawPrincipal` would transfer: replicate the `sharesToReturn` computation (principal-share pro-rata + `forfeitPrizeShares` bonus) without mutating state; return `0` if the round is not `Settled` or the user has no principal.

**Add `getRoundTicketPrice(uint256 rid) external view returns (uint256)`** — returns `rounds[rid].ticketPriceAtRoundOpen`. (Separate getter; do **not** alter the `getRoundInfo` tuple — that would break integrators reading by position.)

### 3. `abi/TicketPrizePoolV4.json`
Regenerate so the new functions are present (the `contracts` CI `check:abi` + `check:deploy-source` gates require source+abi to match).

## Tests — REQUIRED (this is a money-handling deposit path). `test/V4_ShmonDeposit.t.sol`:
1. **Equivalence:** an shMON deposit and a MON deposit for the same `ticketCount` in the same round produce equal `principalShares`, equal tickets, equal `principalAsset`.
2. **Mixed round:** one MON depositor + one shMON depositor; run a full round to settle + draw; assert correct winner payout, forfeit handling, and that **both** withdraw the right shMON via `withdrawPrincipal`.
3. **No under-collection:** `previewRedeem(requiredShares) >= monCost` (vault never credited more value than collected).
4. **Reverts:** paused, stopped, sales ended, `ticketCount == 0`, missing approval, insufficient shMON balance, and `buyTicketsShmon` on an ERC20-mode vault (`ShmonPathNativeOnly`).
5. **`getWithdrawableShares`** equals the actual `withdrawPrincipal` transfer amount across both the normal and the too-few-tickets/forfeit cases.
6. **`getRoundTicketPrice`** returns the snapshot, and still reflects the round-open value after a mid-round `setTicketPrice`.

Run the **full** existing suite (native path must be untouched) + `node scripts/check-production-source-manifest.mjs` + `check:abi` before opening the PR. Use a mock ERC-4626 shMON in tests (mirror the existing yield-vault mock).

## Out of scope
No changes to sponsors, fee router, oracle, multi-winner, pauser, or stop. No ERC20-mode shMON-equivalent path. Anything beyond the three additions above needs a new/updated ADR first.

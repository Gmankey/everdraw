# V4.1 deploy plan — shMON deposit (A now, B at +3.5 days)

**Implements:** ADR-0035. **Gating:** the builder ticket (`v4.1-shmon-deposit-builder-ticket.md`) must be merged to `staging` with green `contracts` CI **before** any mainnet deploy. You cannot deploy code that isn't built and tested — this is the critical path, not the deploy itself.

This reuses the proven mechanics in **`v4-vaultb-cadence-fix-2026-06-03.md`** / **`v4b-deploy-now.md`** (env, role rotation, Sourcify, cutover). Below is only the **delta**.

## Critical path
1. **Build + test + merge** the V4.1 contract change (builder ticket). ← longest pole.
2. **Parity checklist** (`feature-parity-checklist.md`) re-verified against the new build, incl. the new rows: shMON deposit works, `getWithdrawableShares` correct, `getRoundTicketPrice` correct.
3. **Deploy V4.1-A now** (operator funds deployer; builder deploys).
4. **Deploy V4.1-B at +3.5 days** through the stagger guard.
5. Retire old V4-A/V4-B, cut over surfaces, **single Merkl submission on V4.1 addresses**.

### Roles / reserve / keys / Sourcify
Identical to the V4-B runbook: seed VRF reserve, `setKeeper(Fly,true)` + de-authorize deployer, `setPauser(Ledger)`, `transferOwnership(Ledger)` → operator `acceptOwnership` on Ledger, sweep + delete deployer key, Sourcify-verify both the pool and its oracle.

### Retire old vaults
Once V4.1-A is live and the frontend is cut over, `stop()` the **old** native V4-A. Do the same for old V4-B after V4.1-B is live. (The current MON-only vaults are pre-launch; minimal TVL to migrate — but confirm no live principal is stranded before `stop()`; depositors withdraw from their last settled round.)

### Cutover (per surface — verify the live surface, not just the command)
- Frontend `VITE_POOL_ADDRESSES`: slot A → V4.1-A now; slot B → V4.1-B after its deploy. Redeploy Vercel prod; confirm everdraw.xyz shows the vault Open with a working **shMON** deposit option.
- Keeper / indexer Fly secrets → new addresses + deploy blocks (**no `--stage`**).

### Merkl — submit ONCE, on V4.1
Do **not** submit the current MON-only addresses. Coordinate with Merkl/shMonad so they index the **V4.1** addresses from the start. Submit after ≥1 deposit lands on V4.1-A, per `v4-merkl-submission-2026-06-02.md`, using the V4.1 addresses.

## What the PM needs from the operator
- **RETIRED PATTERN (2026-06-12):** do NOT have the PM/builder generate a deployer key. Per `memory/feedback_never_create_throwaway_wallets.md`, the **operator creates or nominates a wallet, funds it (~11 MON), and retains the key.** The old "save key to `.openclaw/secrets/`, recover/delete after" step lost funds twice (V4.1-A/B deployers) and is no longer used. One operator-held wallet per deploy.
- **`acceptOwnership` on the Ledger** for each new vault (verify address on-device).
- **`stop()` the old vaults** on the Ledger when prompted.
